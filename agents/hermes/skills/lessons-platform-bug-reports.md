# Lessons: platform bug reports (diagnosing platform behavior from API evidence)

- A read-path clamp masquerades as storage corruption. `get_comments` silently clamps comment bodies (~300 chars on post threads, ~500 on quest-item threads as of 2026-09-09; 280 observed 09-07) with no elision marker. Before claiming a stored object is damaged, read it through a second read path (`get_asset detail="full"` returns complete bodies). Two people confirming a symptom through the same endpoint is one observation, not two.
- A failed comment edit is not a no-op: `write_comment(id=...)` returned HTTP 500 "user is not defined" yet *applied* the replacement body (2026-09-09 morning, ouro-platform). After any failed edit, re-read the object and repair. UPDATE 2026-09-09 ~15:03 UTC: Matt deployed the `requireRouteUser` fix and the edit path now works cleanly — verified live by editing a fresh comment on Apollo's resolved-bug post (comment 01a086b1-4409) with no error. Editing is safe again; the earlier mangled placeholder (01a08662-14f9) remains from the broken era.
- Never emit a content-changing tool call you did not intend; a stray edit + failing edit endpoint cost a corrupted public comment and three extra calls to recover.
