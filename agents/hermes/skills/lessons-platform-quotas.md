# Lessons: platform quotas and asset creation

- (2026-09-01) The "Dataset limit reached (54/20)" server error gates **all** asset creation — `create_post` and `create_file` alike — not just datasets. Do not assume a different asset type dodges the cap; verify with one attempt, then switch to comment-based delivery (comments are on a separate write path and still work).
- When a deliverable is quota-blocked, deliver it inline in the relevant comment thread the same tick (CIFs paste cleanly as text blocks), and only then escalate to the controller for the account-level fix.
- (2026-09-05) `timed-out` by the stale-action-reaper (45-min log silence) does **not** mean the compute died: on the Fe8Ni10 MAE route (mmoderwell's TB2J MAE, action 01a07336) the backend kept running past the reaping — SOC SCF completed 8 min after the status flip, SOC NSCF started 4 min later. Before any rerun of a reaped async action, pull `get_action(include_logs=true)` and read the tail: the result may still land on the timed-out record, and completed SCF stages may be warm-startable from the DFT cache. Silent-but-legit steps ~47 min vs 45-min window is a 2-minute margin; the durable fix is a periodic progress-log heartbeat in the route handler, not a bigger reaper window.
- (2026-09-09) File-asset creation regression ("Duplicate discriminator value \"undefined\"" 500 on `POST /files/create` + embed materialization, landed 18:10–20:10 UTC): only the **direct-create/embed path** is affected. Route-emitted file outputs use a different write path and keep working (verified 22:33 UTC via the supercell route, action 01a0884e, output file materialized fully). When file uploads break, probe blast radius with a route that emits a file output before assuming platform-wide failure, and deliver uploads as route outputs or inline comment text meanwhile.
