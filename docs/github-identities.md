# GitHub identities

Agents own their repositories. Guardrails live in GitHub, not in a bespoke
self-repo API: the Docker sandbox already has `git` and `gh`, and
`run_shell` inherits whatever `GH_TOKEN` you pass through
`agent.sandbox.env_allowlist`.

This is the same setup an external user should use.

## What each agent needs

1. A GitHub identity of its own (machine user or GitHub App).
2. Write access to **its** repository only.
3. Permission to open pull requests against `ourofoundation/ouro-agents`
   (the public runtime). It must not be able to merge or push to `main`
   there.
4. A fine-grained token (or App installation token) stored as `GH_TOKEN`
   in the agent's `.env`, never in git.

Recommended commit identity, also generated by `ouro-agents init`:

```
GIT_AUTHOR_NAME=<name>
GIT_AUTHOR_EMAIL=<name>@ouro.foundation
GIT_COMMITTER_NAME=<name>
GIT_COMMITTER_EMAIL=<name>@ouro.foundation
```

## Token blast radius

Prefer a GitHub App installed on one agent repo, plus a second
installation (or a narrowly scoped fine-grained PAT) that can open PRs on
`ouro-agents`. Contents: write on the agent's repo; pull requests: write
on `ouro-agents`; no org admin, no repo deletion, no workflow write.

A permission error is a boundary. Do not widen the token to work around
it.

## Branch protection

Protect `main` on every agent repo:

- Require a pull request before merge.
- Require at least one human review (the controller).
- Disallow force pushes and deletions.

Private repositories on GitHub Free cannot use classic branch-protection
APIs. Use [repository rulesets](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets)
when the org plan allows them, or keep `main` human-only by not giving
the agent's token `contents: write` on `main` (write is then limited to
non-default branches / PRs).

## Agent workflow

The always-loaded `git` skill is the procedure: branch, test, commit,
push, `gh pr create`. The `self_improvement` skill adds the Ouro
observe → edit → review → republish loop on top.
